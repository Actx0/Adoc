## Actx0 REST API

Actx0 exposes a versioned HTTP API under `/api/v1`. Use it to manage workspaces, issue keys, run agents and sessions, store messages and memories, version prompts, and search knowledge documents.

Every endpoint page in this reference is generated from the OpenAPI spec — including typed parameters, request/response schemas, language examples, and an interactive **Try it** playground.

<Info>
  **Quick start:** Create a workspace access key in the Actx0 Dashboard, then call Create Memory with `X-Access-Key`.
</Info>

***

## Base URL

```text
http://127.0.0.1:8000/api/v1
```

Self-hosted deployments use your own host with the same `/api/v1` prefix.

***

## Authentication

API requests authenticate with one of:

```bash
X-Access-Key: <workspace-access-key>
```

```bash
X-API-Key: <user-api-key>
```

Or a browser session cookie (`_actx0_session`) for dashboard flows.

| Mode | Header / cookie | Typical use |
| --- | --- | --- |
| Access key | `X-Access-Key` | Agents, SDKs, MCP, and server integrations |
| User API key | `X-API-Key` | User-scoped automation and workspace management |
| Session | `_actx0_session` | Dashboard and interactive apps |

Workspace create/list and `/keys` / `/apiKeys` management require a **user** principal (`X-API-Key` or session). Agents, sessions, messages, memories, prompts, and knowledge accept workspace access keys when the key includes the matching permission.

<Warning>
  **Keep your keys secure.** Never expose them in client-side code or public repositories. Use environment variables and server-side requests only. Create responses return the raw key once — store it immediately.
</Warning>

## Resource hierarchy

```text
/api/v1
  /apiKeys
  /workspaces/{workspaceId}
    /keys
    /prompts
    /promptsByName/{promptName}
    /documents
    /agents/{agentId}
      /sessions/{sessionId}
        /messages
        /memories
```

Sessions can also be addressed by external `id` and/or label query params via `/sessions/by-labels`.

***

## Conventions

- **IDs** are UUIDs.
- **Timestamps** are RFC3339 UTC strings.
- **Pagination** uses `limit` (default `50`, max `100`) and `offset` (default `0`).
- **List responses** use a collection key plus `_meta`:

```json
{
  "memories": [],
  "_meta": { "limit": 50, "offset": 0, "total": 0 }
}
```

- **`meta` fields** on messages/memories: send a JSON **string** in requests; responses return parsed JSON.
- **Errors** always look like:

```json
{ "errorMessage": "Human-readable message" }
```

## Core memory loop

1. **[Create Access Key](/api-reference/create-access-key)** — issue a scoped runtime key
2. **[Create Agent](/api-reference/create-agent)** — create an agent in the workspace
3. **[Create Session](/api-reference/create-session)** — open a conversation session
4. **[Create Memory](/api-reference/create-memory)** — store facts and preferences
5. **[Search Memories](/api-reference/search-memories)** — retrieve relevant context
